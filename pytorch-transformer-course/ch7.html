Chapter 7 · Training, Sampling & Debugging

You have a model that produces logits. This chapter makes it learn and makes it talk: the optimizer, the data pipeline, the exact training loop, autoregressive sampling under no_grad, the verified run that memorizes Alice in Wonderland — and a PyTorch-specific debugging checklist for when it doesn't. By the end you've assembled and run the whole thing.

7.1 The optimizer and the loop

Drop the model into the five-line loop from Chapter 4 — nothing new, just the LM loss reshape (§4.3) as step 3:

model = GPT(vocab).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)

model.train()
for step in range(1, steps + 1):
    inputs, targets = get_batch(...)         # (B, T), (B, T)
    logits = model(inputs)                   # (B, T, V)
    loss = F.cross_entropy(logits.reshape(-1, vocab), targets.reshape(-1))
    opt.zero_grad()                          # clear last step's grads
    loss.backward()                          # fill .grad
    opt.step()                               # update weights

AdamW is the transformer default: Adam (per-parameter adaptive step sizes from running gradient moments) with decoupled weight decay. lr=3e-4 is the classic starting point. The optimizer holds its own state — for Adam, two running averages (m, v) per parameter — and updates weights in place inside its own no_grad region. One worth-knowing property: on the first step, Adam's bias correction makes the update exactly lr · sign(gradient), independent of the gradient's magnitude (it's check 7 of the test suite).

7.2 The data pipeline

The corpus is 2 KB, so we skip DataLoader and sample random windows directly — a vivid use of fancy indexing (§1.3):

def get_batch(data, batch_size, T, device, generator):
    starts = torch.randint(0, len(data) - T - 1, (batch_size,), generator=generator)
    idx = starts[:, None] + torch.arange(T + 1)[None, :]   # (B, T+1) window indices
    return data[idx].to(device)                            # (B, T+1) gather

The index trick: starts[:, None] is (B, 1), arange(T+1)[None, :] is (1, T+1); they broadcast to a (B, T+1) grid of absolute positions, and data[idx] gathers all B windows at once. In the loop we split each window into inputs = batch[:, :-1] and targets = batch[:, 1:] — the next-token shift (§5.6). Passing an explicit generator makes the batch sequence reproducible without touching the global RNG.

7.3 Sampling: generating text

To generate, feed the context, take the last position's logits, turn them into a probability distribution, sample one token, append, repeat. Wrapped in @torch.no_grad() and eval() mode (§3.7), because we're not training:

@torch.no_grad()
def generate(model, idx, n_new, temperature=0.8):
    model.eval()
    for _ in range(n_new):
        idx_cond = idx[:, -model.max_T:]                 # never exceed the pos table
        logits = model(idx_cond)[:, -1, :] / temperature # (B, V): last position only
        probs = F.softmax(logits, dim=-1)
        nxt = torch.multinomial(probs, num_samples=1)    # (B, 1): sample one token
        idx = torch.cat([idx, nxt], dim=1)               # append, grow the sequence
    return idx

The PyTorch-specific moves here: logits[:, -1, :] keeps batch and vocab, drops time — the integer index removes that axis (§1.3). torch.multinomial(probs, 1) draws a token id from the categorical distribution (vs argmax, which would be greedy/deterministic). Temperature divides the logits before softmax: <1 sharpens (more confident, more repetitive), >1 flattens (more random). And idx[:, -model.max_T:] truncates the context so we never index past the learned position table — a real crash if you forget it on long generations.

7.5 A PyTorch debugging checklist

When a transformer (or any model) misbehaves, the cause is almost always one of these — and almost all of them are silent. Work the list top to bottom:

Loss won't go down / explodes
  • Missing zero_grad() (§2.3) — gradients accumulate, training diverges. The single most common cause.
  • Pre-softmaxed the loss (§4.3) — passing probabilities to F.cross_entropy instead of raw logits.
  • Broken graph (§2.5) — a stray .detach()/.item()/no_grad in forward, or a weight built as a bare tensor instead of nn.Parameter, so the optimizer never updates it.
  • Unregistered submodules (§3.3) — blocks in a plain list, not a ModuleList: they run but never train. (The param count catches this — §6.5.)
  • Learning rate — diverging? lower it. Frozen? raise it. 3e-4 is the sane starting point.
First loss is wrong
  • Not near ln V (§5.6) — a fresh model should report ≈ ln(vocab). Far above means broken init or a bug; suspiciously below means label leakage (e.g. a broken causal mask letting the model see the answer).
  • NaN immediately — eps outside the LayerNorm sqrt (§6.1), or masking that fills an entire softmax row with -inf (no visible keys → softmax of all -inf → NaN).
Shape and runtime errors
  • "view size is not compatible … stride" (§1.5) — you view()d after a transpose; add .contiguous() or use .reshape(). This is the attention head-merge.
  • "Expected … Long" (§3.5) — token ids passed as float; nn.Embedding needs long.
  • Device mismatch (§6.4) — a torch.arange/mask created without device=; or you forgot model.to(device) / batch.to(device).
  • "grad can be implicitly created only for scalar" (§2.2) — you called backward() on a non-scalar; reduce the loss with .mean().
Generation looks wrong
  • Forgot model.eval() (§3.7) — dropout still active, corrupting samples (our model has no dropout, but real ones do).
  • Context overflow (§7.3) — generating past max_T without truncating the context indexes off the position table and crashes.
  • Forgot .train() afterward — leaving the model in eval mode silently weakens later training.

Write generate(model, idx, n_new, temperature=0.8): autoregressively append n_new tokens to the prompt idx (shape (B, T0)). Decorate it @torch.no_grad() and put the model in eval(). Four things to get right: truncate the context to max_T, take only the last position's logits, apply temperature before softmax, and sample with multinomial (not argmax). Comments: why multinomial over argmax, and what crashes if you skip the context truncation.

Per step: idx_cond = idx[:, -model.max_T:]; logits = model(idx_cond)[:, -1, :] / temperature; probs = F.softmax(logits, -1); nxt = torch.multinomial(probs, 1); idx = torch.cat([idx, nxt], dim=1).
@torch.no_grad()
def generate(model, idx, n_new, temperature=0.8):
    model.eval()
    for _ in range(n_new):
        idx_cond = idx[:, -model.max_T:]                 # cap context length
        logits = model(idx_cond)[:, -1, :] / temperature # (B, V): last step only
        probs = F.softmax(logits, dim=-1)
        nxt = torch.multinomial(probs, num_samples=1)    # (B, 1)
        idx = torch.cat([idx, nxt], dim=1)
    return idx
# multinomial vs argmax: argmax is greedy/deterministic and gets stuck in
#   loops; multinomial samples from the distribution -> varied, temperature-
#   controllable text.
# no truncation: once the sequence passes max_T, model() indexes the
#   position embedding out of range and crashes (index out of bounds).
