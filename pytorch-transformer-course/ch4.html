Chapter 4 · Data, Losses & the Training Loop

You have tensors (Ch 1), gradients (Ch 2), and modules (Ch 3). This chapter ties them into a model that actually learns: how data gets batched, which optimizer to reach for, the exact shape contract of F.cross_entropy, and the handful of tensor ops — batched matmul, masked_fill, softmax — that the transformer leans on. It ends with a complete classifier you train closed-book.

4.1 Dataset and DataLoader

PyTorch separates "what is one example" (Dataset) from "how do I get batches of them" (DataLoader). A Dataset implements two methods:

from torch.utils.data import Dataset, DataLoader

class CharData(Dataset):
    def __init__(self, data, T):
        self.data, self.T = data, T            # data: 1-D LongTensor of token ids
    def __len__(self):
        return len(self.data) - self.T - 1     # number of valid windows
    def __getitem__(self, i):
        chunk = self.data[i : i + self.T + 1]  # T+1 tokens
        return chunk[:-1], chunk[1:]           # (input, target), each length T

loader = DataLoader(CharData(data, T=64), batch_size=32, shuffle=True)
for inputs, targets in loader:                 # inputs: (32, 64), targets: (32, 64)
    ...

The DataLoader handles shuffling, batching (it stacks the per-example tensors your Dataset returns, adding a leading batch axis), and optional multi-process loading (num_workers). For tiny in-memory data you can skip all this and just index random windows yourself — which is exactly what our reference get_batch does, because the corpus is 2 KB. Know the Dataset/DataLoader API (it's everywhere), but don't think it's mandatory.

4.2 Optimizers

An optimizer is handed the parameters to train at construction, then on each step reads their .grad and updates them:

opt = torch.optim.AdamW(model.parameters(), lr=3e-4)
# ... in the loop ...
opt.zero_grad()
loss.backward()
opt.step()

model.parameters() is the generator of registered tensors from Chapter 3 — this is the payoff of all that registration bookkeeping. The optimizer stores its own state (Adam keeps running averages per parameter) and applies the update in place under the hood. Defaults worth knowing: Adam/AdamW with lr around 3e-4 is the safe transformer default; AdamW is Adam with correct weight decay and is what you'll use. opt.zero_grad() is just the per-parameter .grad reset from Chapter 2, done for the whole model at once.

4.3 F.cross_entropy and its shape contract

For classification (and next-token prediction is classification over the vocabulary), the loss is cross-entropy. F.cross_entropy is the one to use — and its input convention is the single most common shape bug in PyTorch:

cross_entropy(logits, targets): raw logits, integer targets, class axis = 1

It expects raw logits (it applies log_softmax internally — do not softmax first), of shape (N, C), and integer class indices (not one-hot) of shape (N,). The class dimension must be axis 1. It returns the mean negative-log-likelihood as a scalar. Passing probabilities instead of logits, or one-hot targets, gives wrong numbers or an error.

logits = torch.randn(10, 5)          # (N=10, C=5) raw scores
targets = torch.randint(0, 5, (10,)) # (N,) class indices
loss = F.cross_entropy(logits, targets)   # scalar

But a language model produces logits of shape (B, T, V) and targets of shape (B, T) — three axes, not two. The fix is to flatten the batch and time axes together so every (b, t) position becomes one independent classification example:

logits = model(inputs)               # (B, T, V)
loss = F.cross_entropy(
    logits.reshape(-1, V),           # (B*T, V)
    targets.reshape(-1),             # (B*T,)
)

This is exactly the loss line in our transformer.py. reshape(-1, V) collapses (B, T, V) into (B·T, V); reshape(-1) collapses (B, T) into (B·T,); the rows line up position-for-position. (Verify by hand on tiny shapes that the flatten keeps logits and their targets aligned — they do, because both flatten in the same row-major order.)

4.4 Three tensor ops the transformer needs

Batched matmul. The @ operator (a.k.a. torch.matmul) on tensors with more than two axes treats all leading axes as batch dimensions and matrix-multiplies the last two:

a = torch.randn(2, 4, 3, 5)          # (B, H, T, hd)
b = torch.randn(2, 4, 5, 3)          # (B, H, hd, T)
(a @ b).shape                         # (2, 4, 3, 3) — a (3x5)@(5x3) per (B,H) pair

So q @ k.transpose(-2, -1) on (B, H, T, hd) tensors produces all B·H attention-score matrices (B, H, T, T) in one call — no Python loop over heads. This is the heart of why attention is a handful of lines.

masked_fill. Replace entries where a boolean mask is True with a scalar — how the causal mask blocks attention to the future:

scores = scores.masked_fill(future_mask, float("-inf"))   # -inf -> 0 after softmax

softmax with an explicit dim. F.softmax needs to know which axis to normalize over; for attention weights that's the key axis, the last one:

weights = F.softmax(scores, dim=-1)   # each row sums to 1 over the keys

Filling with -inf before softmax works because \(e^{-\infty} = 0\): masked positions get exactly zero weight, and the remaining (visible) positions renormalize to sum to 1.

4.5 The full training loop

Everything assembles. Here is a complete, runnable loop for an MLP classifier — the same skeleton your transformer will use, minus the model:

model = nn.Sequential(nn.Linear(2, 32), nn.ReLU(), nn.Linear(32, 2))
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)

model.train()
for epoch in range(100):
    for xb, yb in loader:              # xb: (B, 2) floats, yb: (B,) class ids
        opt.zero_grad()               # 1. clear grads
        logits = model(xb)            # 2. forward, builds graph -> (B, 2)
        loss = F.cross_entropy(logits, yb)   # 3. scalar loss
        loss.backward()               # 4. fill .grad
        opt.step()                    # 5. update weights

# evaluation: eval mode + no_grad
model.eval()
with torch.no_grad():
    acc = (model(X_test).argmax(-1) == y_test).float().mean()

That five-line inner loop is invariant across essentially all of supervised deep learning — only the model, the data, and the loss change. The transformer in Chapters 6–7 drops into exactly this frame, with F.cross_entropy(logits.reshape(-1, V), targets.reshape(-1)) as step 3.

The five bugs that keep a loop from learning

(1) No zero_grad() → gradients accumulate, loss diverges. (2) Softmaxing before cross_entropy → wrong loss. (3) Wrong cross_entropy shapes → error or silent mislearning. (4) An accidental .detach()/no_grad in the forward path → no gradient reaches the weights. (5) Forgetting model.train()/.eval() toggles → dropout misbehaves. Every one is from Chapters 2–4; together they are most of "why won't my model train."

Write a Dataset for next-token prediction: given a 1-D LongTensor data and context length T, __getitem__(i) returns the pair (input, target) where both have length T and target is input shifted one position right (predict token t+1 from tokens ≤ t). Get __len__ right so no index runs off the end. In a comment, state the shapes DataLoader(ds, batch_size=32) yields and why there's a leading 32.

Grab a window of T+1 tokens at i; the input is the first T, the target is the last T. Valid starts run up to len(data) - T - 1.
class CharData(Dataset):
    def __init__(self, data, T):
        self.data, self.T = data, T
    def __len__(self):
        return len(self.data) - self.T - 1     # last start with a full window
    def __getitem__(self, i):
        chunk = self.data[i : i + self.T + 1]  # T+1 tokens
        return chunk[:-1], chunk[1:]           # input, target — each length T
# DataLoader stacks per-example tensors into a batch, so it yields
# inputs (32, T) and targets (32, T): the leading 32 is the batch axis the
# loader adds by stacking 32 independent windows.

Your model outputs logits of shape (B, T, V) and you have integer targets of shape (B, T). Write the single F.cross_entropy(...) call that computes the mean next-token loss. Then list two specific ways people call cross_entropy wrong (with what happens), and confirm: does it want logits or probabilities?

Flatten batch and time together: logits.reshape(-1, V) and targets.reshape(-1). It wants raw logits and integer (not one-hot) targets.
loss = F.cross_entropy(logits.reshape(-1, V), targets.reshape(-1))
# Wrong way 1: F.cross_entropy(F.softmax(logits, -1), targets) — it applies
#   log_softmax INTERNALLY, so pre-softmaxing double-counts and gives a
#   wrong, too-flat loss.
# Wrong way 2: one-hot targets, or passing (B,T,V) and (B,T) unflattened —
#   shape error (it wants (N,C) logits and (N,) integer class indices).
# It wants RAW LOGITS and INTEGER target indices.

The flatten works because both tensors collapse in the same row-major order, so logit-row k still pairs with target k.

Given q, k, v all of shape (B=2, H=4, T=6, hd=8), write three lines of full (non-causal) attention: the scaled scores, the softmax weights, and the output — predicting each shape. Then add the one line that makes it causal using a lower-triangular mask and masked_fill, and explain why the fill value is -inf and why it goes before the softmax.

Scores: q @ k.transpose(-2,-1) / sqrt(hd) → (B,H,T,T). Mask the upper triangle to -inf, then softmax(dim=-1), then @ v.
import math
scores = q @ k.transpose(-2, -1) / math.sqrt(8)     # (2, 4, 6, 6)
weights = F.softmax(scores, dim=-1)                  # (2, 4, 6, 6), rows sum to 1
out = weights @ v                                    # (2, 4, 6, 8)

# make it causal:
T = q.shape[-2]
mask = torch.tril(torch.ones(T, T, dtype=torch.bool, device=q.device))
scores = scores.masked_fill(~mask, float("-inf"))    # block the future
weights = F.softmax(scores, dim=-1)
out = weights @ v
# -inf BEFORE softmax: e^{-inf}=0, so masked keys get exactly zero weight
# and the visible keys renormalize to sum to 1. Masking AFTER softmax would
# leave the already-normalized weights summing to <1 and leak future info
# into the normalizer.

This is §6.2's attention with the head bookkeeping stripped away — keep it; you'll wrap it in the reshape/transpose dance next chapter.

Capstone — write a complete, runnable training script closed-book: make a 2-D, 2-class toy dataset (e.g. two Gaussian blobs, ~200 points each), define an MLP classifier with nn.Sequential (2 → 32 → ReLU → 2), train it with AdamW and F.cross_entropy for enough steps to fit, then report test accuracy under model.eval() + no_grad. Get the five-line inner loop exactly right, in order. Actually run it and confirm accuracy > 95%.

Data: torch.randn(200,2)+2 for class 1, torch.randn(200,2)-2 for class 0; concat and make a (N,) long target. Loop order: zero_grad → forward → loss → backward → step.
Accuracy: (logits.argmax(-1) == y).float().mean(), computed inside model.eval() and a torch.no_grad() block.
import torch, torch.nn as nn, torch.nn.functional as F
torch.manual_seed(0)

# data: two well-separated blobs
X = torch.cat([torch.randn(200, 2) + 2, torch.randn(200, 2) - 2])
y = torch.cat([torch.ones(200), torch.zeros(200)]).long()      # (400,)

model = nn.Sequential(nn.Linear(2, 32), nn.ReLU(), nn.Linear(32, 2))
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)

model.train()
for step in range(300):
    opt.zero_grad()                       # 1
    logits = model(X)                     # 2  (400, 2)
    loss = F.cross_entropy(logits, y)     # 3  scalar
    loss.backward()                       # 4
    opt.step()                            # 5

model.eval()
with torch.no_grad():
    acc = (model(X).argmax(-1) == y).float().mean()
print(f"loss {loss.item():.3f}  acc {acc.item():.3f}")   # acc ~ 1.000

If you wrote this from an empty editor and it converged, you have the entire training apparatus in hand. The transformer is the same script with a bigger model and the (B,T,V)→(B·T,V) loss reshape. Everything from here is the model.
