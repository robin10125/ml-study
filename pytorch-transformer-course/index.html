A Transformer in PyTorch, from zero

A course about PyTorch the tool, not the transformer the idea. You will build a working GPT-style language model from an empty file — but the real subject is the syntax underneath it: tensors and their shapes, autograd, nn.Module, the training loop. By the last page you can type a transformer into a blank editor, fluently, without looking anything up.

What this course is (and isn't)

There are a hundred explanations of why attention works. This is not one of them. This course assumes you broadly know what a transformer is and trains the other half of the skill: writing one in PyTorch by hand, knowing exactly which tensor operation each line of the diagram becomes, why every .view(), .transpose(), and dim=-1 is where it is, and what breaks if it isn't.

So the emphasis is relentlessly on PyTorch idiom: shapes and broadcasting, the autograd contract, nn.Module and nn.Parameter, the canonical zero-grad/backward/step loop, and the dozen syntax traps (view vs reshape, in-place underscores, biased vs unbiased variance, cross_entropy's shape rules) that separate "I can read PyTorch" from "I can write it."

How this course works

Each chapter is a short textbook — explanations with worked code — followed by a problem set. The problems are where the learning actually happens: you write real PyTorch in the box (it saves automatically) and run it in a live Python session beside the page (pip install torch is the whole setup). The mechanics:

  • Write before you look. Every problem has a code workspace, progressive hints, and a reference solution that stays locked until you've made a genuine attempt. A 📖 Review link jumps to the section the problem draws on, for when you need to re-read.
  • Run your code. Most problems say "predict the shape, then verify" or end with a concrete test (a shape, a number, an assertion). The REPL is the grader — use it before comparing with the reference.
  • Check the box only for problems you solved before opening the reference. Progress is stored locally per chapter and aggregated below; come back to unsolved problems a day later, then after three days.

Your progress

The route

Part I — PyTorch itself (no transformer in sight; just the tool, built into muscle memory):

Ch 1 — Tensors. Creation, dtype and device; indexing and slicing; the broadcasting rules; the reshape family (view, reshape, permute, transpose, unsqueeze) and the contiguity trap; reductions with dim/keepdim; in-place ops and the trailing-underscore convention.

Ch 2 — Autograd. requires_grad and the graph; what .backward() actually does; .grad accumulation and why you zero_grad(); no_grad vs detach vs .item(); leaf vs non-leaf tensors — everything PyTorch hides behind loss.backward().

Ch 3 — nn.Module. The object model: __init__/forward, nn.Parameter, registered buffers, automatic submodule registration, ModuleList vs a plain list; the built-ins (Linear, Embedding, LayerNorm); nn.X vs F.x; state_dict, .to(device), .train()/.eval().

Ch 4 — Data & the loop. Dataset/DataLoader, torch.optim and AdamW, the five-line training loop you'll write forever, F.cross_entropy and its shape convention, batched matmul and masked_fill — capped by an MLP classifier you train closed-book.

Part II — the transformer:

Ch 5 — The Transformer as Tensor Ops. The architecture as a shape pipeline: every box in the diagram named with the exact PyTorch op and tensor shape it becomes — embeddings, scaled dot-product attention, the causal masked_fill, multi-head as a view+transpose, the pre-LN residual block, weight tying.

Ch 6 — The Transformer in PyTorch. Chapter 5's pipeline as ~120 lines of nn.Modules: LayerNorm, CausalSelfAttention, MLP, Block, GPT — each one a problem in the implementation set, each one machine-verified in the companion code.

Ch 7 — Training, Sampling & Debugging. AdamW and the loop, F.cross_entropy reshaping, @torch.no_grad() generation with multinomial sampling, .eval()/device discipline, a PyTorch-specific debugging checklist, and the verified training run that memorizes Alice in Wonderland.

Companion code

In code/, both machine-verified on this machine:

  • transformer.py — the reference single-file model (~210 lines of idiomatic PyTorch; from-scratch LayerNorm, no nn.TransformerEncoder, no tricks). The default run trains a 632 K-parameter character-level LM that fits its corpus (final loss well under 1.0 vs the untrained baseline \(\ln 46 = 3.83\)) and prints a PASS line; expected output is embedded in Chapter 7.
  • test_torch_core.py — seven deterministic checks tying the code to the chapters: hand-built LayerNorm vs nn.LayerNorm, attention vs a per-head manual loop, the causality test, a hand-computed cross-entropy, the \(\ln V\) init loss, autograd vs finite differences (and the grad-accumulation gotcha), and Adam's first-step property. Expect ALL 7 CHECKS PASS.

Setup: python3 -m venv .venv && .venv/bin/pip install torch, then .venv/bin/python code/test_torch_core.py.

Prerequisites

You should know what a transformer is for — attention, multiple heads, a causal language model, what a loss and an optimizer do — at the level of having read a good explainer or watched a lecture. You do not need to derive any of it; Chapter 5 recaps the architecture purely as a shape pipeline. NumPy familiarity helps but isn't required. No PyTorch is assumed — Chapter 1 starts from torch.tensor([1.0]). If you want the math side in depth, the sibling ../jax-transformer-course/ derives the architecture from first principles in JAX.
