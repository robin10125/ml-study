Chapter 5 · The Transformer as Tensor Ops

This is not a chapter about why attention works — you've met that idea. It's about pinning every box in the GPT diagram to the exact PyTorch operation and tensor shape it becomes, so that Chapter 6 is pure transcription. We walk the data from a batch of token ids to a batch of next-token logits, naming the op and tracking the shape at every step.

The shape alphabet (memorize it)

B = batch size · T = sequence length (tokens) · V = vocabulary size · D = d_model, the residual-stream width · H = number of heads · hd = D / H, the per-head width · d_ff = the MLP hidden width (usually 4D). Our reference model: D=128, H=4, hd=32, d_ff=512, n_layers=3. Every shape below is written in these letters.

5.1 The whole pipeline, as shapes

A decoder-only transformer is one function (B, T) ints → (B, T, V) logits. Here is the entire journey, each arrow an operation you already know:

tokens            (B, T)        ints
  │  token_emb lookup  +  pos_emb lookup
  ▼
x                 (B, T, D)     float — the "residual stream"
  │  × n_layers:   x = x + attn(LN(x));  x = x + mlp(LN(x))
  ▼
x                 (B, T, D)
  │  final LayerNorm
  ▼
x                 (B, T, D)
  │  unembed  (× tied embedding matrixᵀ)
  ▼
logits            (B, T, V)     a distribution over the vocab at every position
The residual stream stays (B, T, D) from top to bottom — every block reads it and adds back to it. Only the two ends change rank: the embedding lifts (B,T)→(B,T,D), the unembedding projects (B,T,D)→(B,T,V).

5.2 Embeddings: two lookups that add

The input is a (B, T) LongTensor of token ids. Two nn.Embedding tables turn it into vectors:

  • Token embedding nn.Embedding(V, D): gather a D-vector per token → (B, T, D). (The fancy-index gather from Chapter 1.)
  • Positional embedding nn.Embedding(max_T, D): a learned vector per position 0..T-1, looked up by torch.arange(T) → (T, D), which broadcasts across the batch when added.
pos = torch.arange(T, device=idx.device)            # (T,)
x = token_emb(idx) + pos_emb(pos)                    # (B,T,D) + (T,D) -> (B,T,D)

Why positions at all? Attention is permutation-equivariant — it has no inherent notion of order — so position must be injected as data. The add of a (T, D) onto a (B, T, D) is broadcasting (Chapter 1) doing exactly what it should: the same positional vector added to every batch element.

5.3 Attention, op by op

One head computes, for each position, a weighted average of the value vectors at visible positions, where the weights come from query·key similarity. Multi-head does H of these in parallel on slices of the feature axis. As operations:

stepopshape
project to q, k, vx @ Wq etc. (nn.Linear)(B,T,D) each
split into heads.view(B,T,H,hd)(B,T,H,hd)
head axis forward.transpose(1,2)(B,H,T,hd)
scoresq @ k.transpose(-2,-1) / √hd(B,H,T,T)
causal mask.masked_fill(future, -inf)(B,H,T,T)
weightsF.softmax(dim=-1)(B,H,T,T)
gather valuesweights @ v(B,H,T,hd)
merge heads.transpose(1,2).contiguous().view(B,T,D)(B,T,D)
output projection@ Wo(B,T,D)

Three things to internalize from this table, all pure PyTorch:

  • Heads are a reshape, not a loop. Splitting D into (H, hd) and moving H next to B means batched matmul (§4.4) does all H heads — and all B batch elements — in one @. The view+transpose is the entire multi-head trick.
  • The scale is √hd, not √D. The dot product is over the per-head width hd, so that's the variance to normalize. Using √D is a real bug that just trains worse.
  • Mask with -inf before softmax (§4.4): e^{-∞}=0, so the future gets zero weight and the visible past renormalizes. The mask is lower-triangular (torch.tril) — position t may attend to 0..t.
The contiguity trap, again

After weights @ v you have (B,H,T,hd) with heads on axis 1. To merge heads you transpose(1,2) back to (B,T,H,hd) — but that's now non-contiguous, so a bare .view(B,T,D) raises. You must .contiguous().view(...) (or .reshape(...)). This is the §1.5 trap in its natural habitat; expect to hit it.

5.4 The MLP and the pre-LN block

The per-position MLP is two linears with a nonlinearity, widening to d_ff and back: Linear(D, d_ff) → GELU → Linear(d_ff, D), shape (B,T,D)→(B,T,d_ff)→(B,T,D). It acts independently at every position (no mixing across T — that's attention's job).

A block wraps attention and MLP each in a pre-LN residual: normalize at the entrance of the branch, add the branch output back to the untouched stream.

x = x + attn(ln1(x))      # attention sub-block
x = x + mlp(ln2(x))       # MLP sub-block

Two design points, both consequential in code. Pre-LN (norm inside the branch, before attn/mlp) rather than post-LN keeps an unobstructed residual highway from input to output, which is what lets deep stacks train stably. And the residual x + is not optional decoration: it's the identity path gradients flow down. Drop it and a deep stack stops training (gradients shrink multiplicatively through each block). Each block has two separate LayerNorms — they normalize different activations.

5.5 Final norm and the tied unembedding

After the last block, one more LayerNorm, then project the (B,T,D) stream to (B,T,V) logits. The projection matrix is, by convention, the transpose of the token-embedding matrix — "weight tying":

logits = x @ token_emb.weight.T          # (B,T,D) @ (D,V) -> (B,T,V)

In nn.Module terms that's an nn.Linear(D, V, bias=False) whose .weight is set to share storage with token_emb.weight (both are (V, D), so the Linear computes x @ weight.T — exactly the tie). Tying halves the embedding parameters and ties the "meaning" of a token on the way in and out. Each output vector logits[b,t] is the dot product of the position's representation against every token's embedding — similarity in embedding space, read off as a score.

5.6 From logits to a loss

Training is next-token prediction: from logits (B,T,V) for inputs tokens[:, :-1], predict the targets tokens[:, 1:]. That's the cross_entropy with the (B·T, V) flatten from §4.3:

inputs, targets = tokens[:, :-1], tokens[:, 1:]      # the shift
logits = model(inputs)                                # (B, T, V)
loss = F.cross_entropy(logits.reshape(-1, V), targets.reshape(-1))

One sanity number to carry into the next chapters: an untrained model outputs near-uniform logits, so its loss should sit near \(\ln V\) (for our V=46, that's \(\ln 46 \approx 3.83\)). If your fresh model's first loss is wildly off that, something is wrong before you've trained a single step. We'll use that check explicitly.
