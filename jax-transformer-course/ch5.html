Chapter 5 · The Transformer on Paper

JAX is parked for one chapter. Before implementing anything you need the architecture cold: every tensor, every shape, every design decision and its reason. We build a decoder-only language model — the GPT family shape — because next-token prediction needs no labels and one architecture carries you from toy to frontier.

5.0 The model we will build

One fixed configuration for the rest of the course; all shape drills use it. A character-level language model:

symbolmeaningours
\(V\)vocabulary size (distinct characters)46
\(D\)d_model, width of the residual stream128
\(L\)number of transformer blocks3
\(H\)attention heads4
\(d_h\)head dimension, \(D/H\)32
\(F\)hidden width of the MLP (d_ff)512
\(B, T\)batch size, sequence length32, 64

The whole pipeline, tokens to loss:

tokens (B, T) ints
  ├─ token embedding + position embedding ──► x: (B, T, D)   the residual stream
  │    repeat × L:
  │      x = x + Attention( LayerNorm(x) )      ← tokens talk to each other
  │      x = x + MLP( LayerNorm(x) )            ← each token thinks alone
  ├─ final LayerNorm
  ├─ unembed (embedding matrix transposed) ──► logits: (B, T, V)
  └─ cross-entropy against tokens shifted left by one ──► scalar loss

Two structural facts to internalize now. The residual stream \(x\) is the spine: blocks read from it and add their contribution back, so information (and gradients) can flow from layer 0 to the loss untouched — this additive highway is why deep transformers train. And attention is the only place where positions exchange information; everything else acts on each position independently.

5.1 Embeddings: from ids to vectors

A token id is a meaningless integer; the model needs vectors. The embedding table \(E \in \mathbb{R}^{V \times D}\) is a learned matrix; "embedding token 17" is just reading row 17. For a batch of ids this is pure indexing: E[tokens] maps (B, T) ints to (B, T, D) floats.

Attention, as you'll prove in a moment, treats its input as a set — it has no idea token 3 comes before token 4. So we add a second learned table, the position embedding \(P \in \mathbb{R}^{T_{max} \times D}\), giving every position its own vector:

$$ x_{b,t} = E_{\text{tokens}[b,t]} + P_t. $$

Same word at a different position ⇒ different starting vector. Learned absolute positions are the simplest scheme that works (the original GPT choice); sinusoidal tables and rotary embeddings (RoPE) are drop-in alternatives you can explore later — the architecture around them is unchanged.

5.2 Attention from first principles

Each position holds a vector; positions need to exchange information ("what noun does this pronoun refer to?"). Attention is a differentiable dictionary lookup. From every token's vector we project three things:

  • a query \(q_t = x_t W_Q\) — "what am I looking for?"
  • a key \(k_t = x_t W_K\) — "what can I be found by?"
  • a value \(v_t = x_t W_V\) — "what do I hand over if you look at me?"

Token \(i\) scores every token \(j\) by the dot product \(q_i \cdot k_j\), softmaxes the scores into weights, and takes the weighted average of the values:

$$ \mathrm{Attn}(x)_i = \sum_j \underbrace{\mathrm{softmax}_j\!\Big( \frac{q_i \cdot k_j}{\sqrt{d_h}} \Big)}_{w_{ij}} \, v_j, $$

followed by an output projection \(W_O\). The output is a convex combination of value vectors: attention can blend and retrieve what tokens offer, never invent content beyond it.

Why divide by \(\sqrt{d_h}\)?

A dot product of \(d_h\) independent unit-variance terms has variance \(d_h\) — standard deviation \(\sqrt{d_h}\). With \(d_h = 32\), raw scores would spread over roughly \(\pm 5.7\) instead of \(\pm 1\), and softmax of widely spread inputs saturates: one weight \(\approx 1\), the rest \(\approx 0\), gradients through the softmax \(\approx 0\). Dividing by \(\sqrt{d_h}\) restores unit variance at any head size, keeping the attention distribution soft and trainable. Tiny constant, disproportionate consequences.

5.3 The causal mask

A language model predicts token \(t+1\) from tokens \(\le t\). But raw attention lets every position see every other — including the future, where the answer literally sits. The fix: before the softmax, set every score \(q_i \cdot k_j\) with \(j > i\) to \(-\infty\):

$$ \tilde s_{ij} = \begin{cases} s_{ij} & j \le i \\ -\infty & j > i \end{cases} \qquad \Rightarrow \qquad e^{-\infty} = 0 \text{ inside the softmax.} $$

The mask is a lower-triangular boolean matrix (tril). Two details people get wrong:

  • Mask before softmax, not after. Softmax normalizes over everything it sees. Zeroing weights after softmax leaves the visible weights summing to less than 1 (the future stole mass) — outputs silently shrink. Masking with \(-\infty\) before means the softmax renormalizes over visible tokens only: a proper distribution.
  • The diagonal stays. A token may attend to itself; row 0 attends only to itself. (All-\(-\infty\) rows would produce NaNs.)

The mask is also why training is parallel: with masking, position \(t\)'s output depends only on tokens \(\le t\), so every position is simultaneously a correct training example — one forward pass yields \(T\) next-token predictions, not 1.

5.4 Multi-head attention

One attention pattern per layer is a bottleneck: the softmax weights sum to 1, so attending strongly to one relationship means ignoring others. Multi-head attention runs \(H\) independent attentions in parallel, each in a smaller subspace of size \(d_h = D/H\), then concatenates:

  1. Project once: \(Q = x W_Q\), \(K = x W_K\), \(V = x W_V\), each \((B, T, D)\).
  2. Reshape the last axis into \((H, d_h)\) and treat each of the \(H\) slices as its own attention problem: scores \((B, H, T, T)\), mask, softmax, weighted values \((B, H, T, d_h)\).
  3. Concatenate heads back to \((B, T, D)\) and apply the output projection \(W_O \in \mathbb{R}^{D \times D}\), which lets heads' contributions mix.

Note what's not there: no extra parameters versus single-head (same four \(D \times D\) matrices — the heads are a reshape, not new projections), and the per-head scale is \(\sqrt{d_h}\), not \(\sqrt{D}\) — a classic implementation bug. Different heads learn visibly different functions: previous-token heads, syntax heads, induction heads.

5.5 LayerNorm and the pre-LN residual block

Residual addition lets activations grow without bound as contributions accumulate; downstream blocks would face inputs of wildly varying scale. LayerNorm re-standardizes each token vector independently — mean 0, variance 1 across the \(D\) features — then applies a learned per-feature scale \(\gamma\) and shift \(\beta\):

$$ \mathrm{LN}(x) = \frac{x - \mu(x)}{\sqrt{\sigma^2(x) + \varepsilon}} \odot \gamma + \beta, \qquad \mu, \sigma^2 \text{ over the feature axis only.} $$

Crucially: statistics are per-token, over features — not over the batch (that's BatchNorm, which would leak information across examples and break at small batch / generation time). \(\varepsilon\) guards the division; \(\gamma, \beta\) restore expressiveness (the network can undo the normalization where it helps).

Placement matters. The modern arrangement is pre-LN: normalize the input of each sub-block, inside the residual branch:

$$ x \leftarrow x + \mathrm{Attn}(\mathrm{LN}_1(x)), \qquad x \leftarrow x + \mathrm{MLP}(\mathrm{LN}_2(x)). $$

The residual path itself is never normalized — there is an identity route from embedding to loss, so gradients reach early layers unattenuated; pre-LN models train stably without the warmup gymnastics the original post-LN arrangement required. A final LayerNorm cleans up the stream before the unembedding.

The MLP sub-block is the simple half: two matrices with a GELU between, \(\mathrm{MLP}(x) = \mathrm{GELU}(xW_1 + b_1)W_2 + b_2\), expanding \(D \to F = 4D \to D\), applied to every position independently. Attention gathers; the MLP processes.

5.6 The loss: every position predicts its successor

After the final LayerNorm we need logits over the vocabulary. Rather than a new \((D, V)\) matrix, reuse the embedding: \(\text{logits} = x E^\top\) — weight tying. It saves \(V \times D\) parameters, and it's principled: embedding and unembedding are near-inverse maps between token space and vector space, and tying consistently helps at small scale.

Training pairs come from the famous shift: feed tokens[:-1], predict tokens[1:] — position \(t\)'s logits are graded against the actual next token. Thanks to the causal mask all \(T\) predictions are valid simultaneously, so a \((B, T+1)\) batch yields \(B \cdot T\) supervised examples per step. The loss at each position is cross-entropy, \(-\log p_\theta(\text{correct token})\), averaged:

$$ \mathcal{L} = -\frac{1}{BT} \sum_{b,t} \log\, \mathrm{softmax}\big(\text{logits}_{b,t}\big)_{\text{targets}_{b,t}}. $$
The most useful number in deep learning: \(\ln V\)

Before training, logits are near-random ⇒ the softmax is near-uniform ⇒ each correct token has probability \(\approx 1/V\) ⇒ loss \(\approx \ln V\). For our \(V = 46\): \(\ln 46 \approx 3.83\). Check this on the very first step, every time you build a model. Loss far above \(\ln V\): broken init (scales too big). Loss below it at step 0: information is leaking — almost always a causal-mask bug letting positions see their own targets. One printed number catches the two worst transformer bugs.
