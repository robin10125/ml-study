Chapter 4 · Pytrees: Parameters, Optimizers & scan

If a model is a function forward(params, x), then params for a real network is hundreds of arrays. The pytree is JAX's answer to organizing them — and jax.tree.map is how a one-line SGD update touches all of them at once. By the end of this chapter you'll have every JAX skill the transformer needs: you'll build, train, and jit a complete MLP pipeline.

4.1 What a pytree is

A pytree is any nested structure of Python containers — dicts, lists, tuples — with arrays (or scalars) at the leaves:

params = {
    "layer1": {"W": jnp.zeros((784, 256)), "b": jnp.zeros(256)},
    "layer2": {"W": jnp.zeros((256, 10)),  "b": jnp.zeros(10)},
}
jax.tree.leaves(params)      # [W1, b1, W2, b2] — 4 leaf arrays, depth-first

JAX transformations treat pytrees as first-class: you can grad with respect to one, pass one through jit, vmap over one. jax.grad(loss)(params, …) returns a pytree with the same structure as params — gradient of params["layer1"]["W"] sits at grads["layer1"]["W"]. The workhorse operation is:

jax.tree.map(f, tree)             # apply f to every leaf
jax.tree.map(f, tree_a, tree_b)   # zip two trees of IDENTICAL structure,
                                  # apply f leaf-pairwise

That second form is the whole secret of JAX optimizers: params and grads have identical structure, so "subtract lr times the gradient, everywhere" is one call (§4.3). Structure mismatch (a missing key, a list where the other has a tuple) raises immediately — a feature, since it catches wiring bugs at the boundary.

A pytree is any nesting of registered containers (dict, list, tuple, …) whose non-container contents are leaves. The example has 4 leaves: ones(2), ones(3), ones(4), and the scalar 5.0 (scalars are leaves too). tree.map(x*0) returns the same structure with every leaf zeroed (the scalar becomes 0.0). The two-tree form requires identical structure — same containers, same keys, same nesting — and that's guaranteed for params/grads because jax.grad constructs the gradient tree to mirror the parameter tree exactly: every parameter array is paired with its own gradient array by position in the structure.

4.2 Initialization: pure functions of a key

With no nn.Module to initialize itself, you write the init function: it takes a key, splits it, and returns the params pytree. Two disciplines from earlier chapters meet here — key splitting (§1.4), and a new one: scale.

def init_mlp(key, sizes):                  # sizes = [784, 256, 256, 10]
    params = []
    for n_in, n_out in zip(sizes[:-1], sizes[1:]):
        key, wk = jax.random.split(key)
        params.append({
            "W": jax.random.normal(wk, (n_in, n_out)) / jnp.sqrt(n_in),
            "b": jnp.zeros(n_out),
        })
    return params                          # a list of dicts — a fine pytree

Why / jnp.sqrt(n_in)? Each output unit is a dot product of \(n_{in}\) terms. If inputs and weights have unit variance, the sum of \(n_{in}\) independent products has variance \(n_{in}\) — activations would grow by \(\sqrt{n_{in}}\) at every layer, exponentially with depth. Scaling weights by \(1/\sqrt{n_{in}}\) makes each layer roughly variance-preserving, so signals (and, symmetrically, gradients) neither explode nor vanish. This is the same fan-in reasoning behind PyTorch's default Kaiming/Xavier inits — here you apply it by hand, and the transformer's init_params in Chapter 6 uses exactly this rule.

Var of a sum of n independent zero-mean products = n × (var of one product). What scale on the weights cancels it?
Same key + same shape ⇒ same numbers (§1.4). What do layers 1 and 2 of width (256, 256) then look like?

Code as in §4.2 (split per layer; normal(wk, (n_in, n_out)) / sqrt(n_in); zeros(n_out)). Justification: \(y_j = \sum_{i=1}^{n_{in}} x_i W_{ij}\) with unit-variance independent terms has \(\mathrm{Var}(y_j) = n_{in}\sigma_W^2\); choosing \(\sigma_W = 1/\sqrt{n_{in}}\) gives unit output variance, so activation scale is depth-independent (and the backward pass inherits the same protection). Key reuse: any two layers with equal shapes get bit-identical weight matrices — hidden layers compute identical functions, halving effective capacity, with no error and no obvious symptom beyond a mysteriously weak model.

4.3 Optimizers are three lines of tree.map

Gradient descent over every parameter simultaneously:

params = jax.tree.map(lambda p, g: p - lr * g, params, grads)

That's SGD, whole-model, one line. Optimizers with memory — momentum, Adam — need somewhere to keep their running statistics. In PyTorch that state hides inside the optimizer object. Purity forbids that here: optimizer state is one more pytree you hold and thread, same shape as params:

def sgd_momentum_init(params):
    return jax.tree.map(jnp.zeros_like, params)            # velocity v

def sgd_momentum_update(params, grads, v, lr, mu=0.9):
    v = jax.tree.map(lambda v, g: mu * v + g, v, grads)
    params = jax.tree.map(lambda p, v: p - lr * v, params, v)
    return params, v                                       # BOTH come back out

The update is pure: state in as an argument, new state out as a return value. If you tried to keep v in a Python attribute instead, §3.3 told you the ending — it gets baked into the first trace and never updates. Full Adam (running mean and variance, plus bias correction) follows the identical pattern with two state trees; you'll write it in Chapter 7.

The update runs inside a jitted train step. What happens to non-argument values at trace time?

SGD: params = jax.tree.map(lambda p, g: p - lr*g, params, grads). Momentum: init v = tree.map(zeros_like, params); update v = tree.map(λv,g: mu*v+g, v, grads) then params = tree.map(λp,v: p-lr*v, params, v); return both. An attribute would be closure-captured at trace time (§3.3): the jitted train step would compile with the initial all-zeros velocity as a frozen constant, so momentum would silently never accumulate. Arguments are tracers — live inputs — which is precisely what state that changes every step must be.

4.4 The canonical training step

Assemble §§4.1–4.3 and Chapter 2's value_and_grad and you get the JAX training pattern — worth memorizing as a shape, because Chapter 7's transformer step is this exact function with a bigger loss:

@jax.jit
def train_step(params, opt_state, batch):
    loss, grads = jax.value_and_grad(loss_fn)(params, batch)
    params, opt_state = optimizer_update(params, grads, opt_state)
    return params, opt_state, loss        # everything that changed, returned

for step in range(n_steps):
    key, bkey = jax.random.split(key)
    batch = sample_batch(bkey, data)
    params, opt_state, loss = train_step(params, opt_state, batch)

Read it as a checklist: every changing thing (params, opt_state, the data, keys) enters as an argument; every changing thing exits as a return value; the loop's only job is to rebind names and split keys. The whole step is one jit unit (§3.5), so XLA fuses forward, backward, and update into a single compiled program with no Python in the hot path.

Code as in §4.4. Arguments: params, opt_state, batch (and step/key if the step uses them). Returns: new params, new opt_state, metrics. (a) The first-trace value of lr is baked in; your "annealing" does nothing — pass lr (or step) as an argument. (b) The function computes the new optimizer state and throws it away; you keep feeding the old one — momentum/Adam statistics never accumulate, training quietly behaves like plain SGD with bias-corrected noise. (c) The closed-over key is frozen, so every step trains on the identical batch: loss plummets, the model has memorized one batch, generalization is zero. All three are silent — which is why the audit habit matters.

4.5 lax.scan: compiled loops

A Python for loop under jit unrolls: 1000 iterations means a 1000-copy program — slow to compile, sometimes slow to run. jax.lax.scan compiles the body once and loops at runtime, while also stacking per-step outputs:

def step(carry, x):                  # carry: loop state; x: this step's input
    new_carry = carry + x
    y = new_carry ** 2               # anything you want recorded per step
    return new_carry, y

final, ys = jax.lax.scan(step, 0.0, jnp.arange(5.0))
# final = 10.0 (0+1+2+3+4);  ys = [0, 1, 9, 36, 100] — stacked per-step outputs

Signature to memorize: scan(f, init_carry, xs) where f(carry, x) → (carry, y); returns (final_carry, stacked_ys). The carry must keep the same shape/dtype every iteration (it's compiled once). Uses in practice: RNNs (carry = hidden state), running whole training epochs inside one compiled call (carry = (params, opt_state, key), xs = batches), and stacking identical transformer layers (carry = activations, xs = per-layer params). Our 3-layer model just unrolls a Python loop — fine at this depth — but you should recognize scan when you see it in production JAX.

Why does scan beat a Python loop under jit, and what constraint does the carry have to satisfy?

Body: (carry, x) → (carry, y). For the running sum, the carry and the per-step output happen to be the same value.
def body(c, x):
    c = x + 0.9 * c
    return c, c                       # new carry, recorded output

_, cs = jax.lax.scan(body, 0.0, xs)

scan(f, init, xs) with f(carry, x) → (new_carry, y) returns (final_carry, ys) where ys stacks the per-step ys along a new leading axis. Under jit, a Python loop is unrolled into N copies of the body (compile time and code size grow with N); scan compiles the body once with a runtime loop. Constraint: the carry's structure, shapes, and dtypes must be identical across iterations — the compiled body is reused, so the loop state can't change signature. (Fun fact from the PPO/GAE world: discounted sums like this one are exactly what scan is great at.)

4.6 Checkpoint: a complete pipeline, no framework

Everything you now know, in one runnable program — a two-layer MLP regressing \(y = \sin(3x)\). This is the full anatomy of every JAX project, the transformer included; only forward and loss_fn will grow.

import jax, jax.numpy as jnp

def init_mlp(key, sizes):                                  # §4.2
    params = []
    for n_in, n_out in zip(sizes[:-1], sizes[1:]):
        key, wk = jax.random.split(key)
        params.append({"W": jax.random.normal(wk, (n_in, n_out)) / jnp.sqrt(n_in),
                       "b": jnp.zeros(n_out)})
    return params

def forward(params, x):                                    # pure function (§1.3)
    for layer in params[:-1]:
        x = jnp.tanh(x @ layer["W"] + layer["b"])
    return x @ params[-1]["W"] + params[-1]["b"]

def loss_fn(params, x, y):
    return jnp.mean((forward(params, x) - y) ** 2)

@jax.jit                                                   # whole step (§3.5)
def train_step(params, x, y):                              # §4.4
    loss, grads = jax.value_and_grad(loss_fn)(params, x, y)
    params = jax.tree.map(lambda p, g: p - 0.05 * g, params, grads)
    return params, loss

key = jax.random.PRNGKey(0)
key, ik, xk = jax.random.split(key, 3)                     # §1.4
params = init_mlp(ik, [1, 64, 64, 1])
x = jax.random.uniform(xk, (256, 1), minval=-2.0, maxval=2.0)
y = jnp.sin(3 * x)

for step in range(2000):
    params, loss = train_step(params, x, y)
print(loss)        # ≈ 1e-4: an MLP fit by pure functions all the way down
