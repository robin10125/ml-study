Chapter 2 · grad: Differentiation as a Function Transform

In PyTorch, differentiation is something that happens to tensors: a tape records your forward pass, backward() replays it, gradients precipitate into .grad fields. In JAX, differentiation is something that happens to functions: jax.grad eats a function and returns its derivative — another ordinary function you can call, compose, jit, or differentiate again.

2.1 grad eats a function, returns a function

def f(x):
    return x**3 + 2*x

df = jax.grad(f)        # df is a new Python function computing f'
df(2.0)                 # 3·4 + 2 = 14.0
jax.grad(jax.grad(f))(2.0)   # f'' = 6x  ⇒  12.0 — it composes

Three rules govern jax.grad:

  1. The function must return a scalar. A gradient \(\nabla f\) is defined for \(f: \mathbb{R}^n \to \mathbb{R}\). Losses are scalars, so this is no restriction for training. (For vector-valued outputs you'd use jax.jacobian; we won't need it.)
  2. By default it differentiates with respect to the first argument. jax.grad(loss_fn)(params, batch) returns \(\partial \text{loss}/\partial \text{params}\) and treats batch as a constant. Want a different argument, or several? argnums=1 or argnums=(0, 1).
  3. The argument can be any nested structure of arrays — a dict of dicts of matrices is fine. The gradient comes back with exactly the same structure: one gradient array per parameter array, in the same place. (This is the "pytree" idea; Chapter 4 is devoted to it.)

Notice what's absent compared to PyTorch: there is no requires_grad flag (what gets differentiated is chosen by argument position, not by tensor attributes), no graph being silently recorded as you compute (you ask for a derivative explicitly, of a specific function), and no .grad fields (gradients are plain return values).

2.3 value_and_grad and has_aux: the training-step workhorses

In training you want the loss and the gradient. Calling f and grad(f) separately would run the forward pass twice. The fused version is what every real JAX training step uses:

loss, grads = jax.value_and_grad(loss_fn)(params, batch)

Often the loss function also produces side information — accuracy, logits, a breakdown of loss terms. But grad demands a scalar output. The escape hatch is has_aux=True: your function returns a pair (scalar_loss, anything_else), and only the scalar is differentiated:

def loss_fn(params, batch):
    logits = forward(params, batch["x"])
    loss = cross_entropy(logits, batch["y"])
    acc = (logits.argmax(-1) == batch["y"]).mean()
    return loss, {"acc": acc, "logits": logits}     # (scalar, aux)

(loss, aux), grads = jax.value_and_grad(loss_fn, has_aux=True)(params, batch)

Note the nesting on the left: the value slot holds the full (loss, aux) pair, the second slot holds grads. Getting this unpacking wrong is a rite of passage; commit it to memory now.

def loss_fn(params, x, y):
    pred = forward(params, x)
    return jnp.mean((pred - y)**2), pred

(loss, pred), grads = jax.value_and_grad(loss_fn, has_aux=True)(params, x, y)

It returns a pair whose first element is the function's full return value (loss, pred) and whose second is the gradient of the scalar only, shaped like params. has_aux exists because grad requires a scalar to differentiate; the flag lets a function smuggle out extra (undifferentiated) results without violating that rule.

2.4 stop_gradient: cutting one wire

Sometimes a value should be used in the forward computation but treated as a constant by differentiation — PyTorch's .detach(). JAX spells it jax.lax.stop_gradient:

# TD-style bootstrap target: learn V to match r + γ·V(s'), but do NOT
# differentiate through the target's own V — it's playing "ground truth"
target = reward + gamma * jax.lax.stop_gradient(value_fn(params, s_next))
loss = jnp.mean((value_fn(params, s) - target)**2)

Without stop_gradient here, grad would also push value_fn(params, s_next) toward the residual — the optimizer chases its own moving prediction (a known instability in bootstrapped value learning) instead of regressing prediction onto target. The same tool builds straight-through estimators and freezes submodules. Identity in the forward pass; zero in the backward pass.

Forward: identity. Backward: …? In the TD loss there are two appearances of params — gradient should flow through exactly one.

Forward: identity (value passes through unchanged). Backward: gradient is exactly zero through it — differentiation treats it as a constant. Twin: .detach().

target = r + gamma * jax.lax.stop_gradient(V(params, s_next))
loss = jnp.mean((V(params, s) - target)**2)

With the stop, \(\nabla\text{loss}\) contains only the term pulling \(V(s)\) toward the target. Without it, an extra term \(-\gamma \cdot \nabla V(s')\) appears, pushing the target toward the prediction too — the regression becomes a pursuit of a moving point it itself controls, which biases learning and is a classic source of divergence.

2.5 What grad actually does (one level down)

You don't need autodiff internals to use JAX, but one mental model prevents superstition. jax.grad(f)(x): (1) traces f at the abstract shape of x, recording each primitive operation into a small intermediate program (a jaxpr); (2) transforms that program into one computing the derivative (reverse-mode: forward pass storing residuals, then a backward sweep — same math as PyTorch's tape, built ahead of time from the traced program rather than recorded during execution); (3) runs it. PyTorch's tape is rebuilt by every forward pass at runtime; JAX's derivative program is constructed from the trace and — under jit — compiled once and reused. The practical consequences:

  • Python control flow (if/for on concrete values) is resolved during tracing — the derivative program sees only the branch actually taken (more in Chapter 3).
  • Memory behaves like PyTorch: reverse mode stores activations for the backward sweep.
  • Because "derivative of a program" is itself a program, transformations stack arbitrarily: jit(grad(f)), grad(grad(f)), vmap(grad(f)) all just work.

PyTorch constructs its graph dynamically during every forward execution; JAX constructs it once from a trace, ahead of execution. Consequences: under jit the whole loss-and-gradient computation compiles to one reusable XLA program (no per-step graph-building overhead); Python control flow is frozen at trace time (a branch on data needs special handling — Chapter 3); and transformations compose freely since the output of one transform is a valid input to another (vmap(grad(f)), grad(grad(f))).
