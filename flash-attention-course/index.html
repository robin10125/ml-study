⚡ Flash Attention, From Scratch

A rigorous, recall-driven course that takes you from "what is attention?" to writing a FlashAttention-2-style kernel in CUDA and in JAX.

What you will be able to do

By the end of this course you will be able to:

  • Explain precisely why standard attention is slow on GPUs (it is not the FLOPs), using memory-hierarchy arguments with real numbers.
  • Derive the online-softmax recurrence and prove it computes exact softmax — the single mathematical trick that makes Flash Attention possible.
  • State the FlashAttention-2 forward and backward algorithms from memory, including the three specific changes FA-2 made over FA-1.
  • Write, compile, and verify a working FlashAttention-2-style forward kernel in CUDA, and a backward kernel, against a reference implementation.
  • Implement Flash Attention in JAX twice: as a blockwise lax.scan with a custom_vjp, and as a Pallas GPU kernel.
The one-sentence summary of this entire course
Flash Attention computes exactly the same output as standard attention, with more arithmetic, but runs faster because it never writes the \(N \times N\) attention matrix to slow GPU memory — and the only mathematical obstacle to doing that, the softmax normalizer that seems to need all scores at once, is removed by an online softmax that incrementally corrects earlier work as new scores arrive.

How to study this course (read this — it changes your results)

This course is built around active recall: you will constantly be asked to produce knowledge before being shown it. Purple Recall boxes appear throughout. For each one:

  1. Answer out loud or on paper first. Actually write the equation or code. Reading the solution and thinking "yeah, I knew that" produces an illusion of knowledge that collapses the moment you face an empty .cu file.
  2. Stuck? Click 💡 Hint — hints are progressive, so take them one at a time and re-attempt after each.
  3. If a hint isn't enough, the 📖 Review link jumps to the exact section of the lesson that teaches the needed concept. Re-read it, come back, and try again without looking.
  4. Only then click Show solution, and grade yourself honestly with the "recalled correctly from memory" checkbox. Your progress is saved in your browser and shown in the sidebar and below.
  5. Return to unchecked recalls tomorrow, then in three days. Spaced repetition is not optional decoration; it is how the CUDA chapter becomes writable from memory.

The coding chapters (5–7) are workbooks: each kernel is built as a sequence of recall exercises, and the full verified program is given at the end. You will get far more out of them if you keep a terminal open and actually compile as you go.

Prerequisites

  • Comfortable linear algebra: matrix multiplication, transposes, shapes.
  • You have seen the transformer attention formula before (we re-derive everything, but it shouldn't be your first exposure).
  • Basic C/C++ reading ability for the CUDA chapters; basic Python/NumPy for the JAX chapter.
  • No CUDA or GPU-architecture knowledge is assumed. Chapter 2 builds it from zero.
  • To run the code: any NVIDIA GPU + nvcc for chapters 5–6; pip install jax for chapter 7 (the Pallas kernel can run in interpreter mode on CPU).

Notation used everywhere

SymbolMeaning
\(N\)sequence length (number of tokens)
\(d\)head dimension (e.g. 64 or 128); per-head, after splitting the model dimension across heads
\(Q, K, V \in \mathbb{R}^{N \times d}\)query, key, value matrices for one head of one sequence
\(S = QK^\top / \sqrt{d} \in \mathbb{R}^{N \times N}\)(scaled) score matrix
\(P = \mathrm{softmax}_{\text{row}}(S)\)attention weights; each row sums to 1
\(O = PV \in \mathbb{R}^{N \times d}\)attention output
\(B_r, B_c\)tile sizes: rows (queries) and columns (keys) per block
\(T_r = \lceil N/B_r \rceil,\; T_c = \lceil N/B_c \rceil\)number of query / key tiles
\(m, \ell\)running row max and running softmax denominator (the online-softmax state)
\(L = m + \log \ell\)row log-sum-exp, the only softmax statistic saved for backward
HBM / SRAMlarge, slow off-chip GPU memory / small, fast on-chip memory (shared memory + registers)
