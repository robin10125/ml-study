Part 1

The JAX mental model & the skeleton

🔒 Locked — finish the warm-up first.

We build with no framework — no Flax, no Haiku. Just jax.numpy functions and plain Python dicts of arrays. This forces the two ideas that make JAX JAX:

  1. Functions are pure. A model is not an object with hidden state; it is a function forward(params, tokens) → logits. All state — every weight — enters through the front door as an argument. Parameters live in a pytree: a nested structure of dicts/lists with arrays at the leaves. JAX transformations (grad, jit, vmap) operate on whole pytrees transparently.
  2. Randomness is explicit. No global seed. You hold a PRNG key, and you jax.random.split(key) every time you need fresh randomness. Same key in, same numbers out, always.

Check 1.1Suppose you hide the weights in a Python object and mutate them in-place inside a method, then wrap that method in @jax.jit. What actually goes wrong?

Correct

jit runs your Python once with abstract tracer values and compiles the result. Anything not passed as an argument is captured at trace time and frozen. Your "training" would compute gradients against the initial weights forever. This single fact explains the entire JAX style: params go in as arguments, updated params come out as return values. Nothing is ever mutated.

The skeleton we will build 
tokens (B, T) ints
  └─ embedding lookup ──────────────► x: (B, T, d_model)   "the residual stream"
       repeat × n_layers:
         x = x + Attention( RMSNorm(x) )     # GQA + RoPE inside

  └─ final RMSNorm
  └─ unembed (tied with embedding) ─► logits: (B, T, vocab)

Two things to internalize. First, the residual stream is the spine: every block reads from it (through a norm) and adds its contribution back. Gradients flow unimpeded through the additions, which is why 100-layer transformers train at all. Second, this is pre-norm: normalize the input of each sub-block, not its output — empirically far more stable than the original post-norm arrangement.

Part 2

RMSNorm: the smallest real component

🔒 Locked — finish the check and both drills in Part 1.

Before every attention and FFN block, we normalize the residual stream. Modern models (Llama, Mistral, &c.) use RMSNorm, a stripped-down LayerNorm: no mean subtraction, no bias — just divide each token's vector by its root-mean-square, then scale by a learned per-dimension gain γ.

y = x / RMS(x) · γ,   where RMS(x) = √( mean(x²) + ε )

Compute 2.1By hand: x = [3, 4], γ = [1, 1], ignore ε. What is the second component of RMSNorm(x)? (2 dp)

mean(x²) = (9 + 16) / 2 = 12.5. Now take the square root, then divide.
Answer

RMS = √12.5 ≈ 3.536, so y₂ = 4 / 3.536 ≈ 1.13. Notice the output vector always has RMS ≈ 1 (before γ): the block downstream always sees inputs at a predictable scale, no matter how large the residual stream has grown.

Code 2.2Write rms_norm(x, gamma, eps=1e-6) in jax.numpy. It must work for x of shape (B, T, d), normalizing over the last axis only. Think: which axis, and what keeps the broadcast working?

Write a real attempt first (80+ characters). Better: run it on a random (2, 3, 4) array and check the output's RMS is ≈ 1.

Reference 
def rms_norm(x, gamma, eps=1e-6):
    ms = jnp.mean(x * x, axis=-1, keepdims=True)      # (B, T, 1)
    return x * jax.lax.rsqrt(ms + eps) * gamma        # broadcast over d

Self-grade — your version must have:

  • axis=-1 (per-token, over features — not over the batch or time!)
  • keepdims=True (or a manual [..., None]) so the division broadcasts
  • ε inside the square root, guarding against an all-zero token
  • γ multiplied last, shape (d,), broadcasting over (B, T)

Why no mean subtraction or bias? Empirically they buy nothing in transformers, and removing them is faster and simpler. The params for this layer are just γ, initialized to ones.

Part 3

RoPE: positions as rotations

🔒 Locked — finish the computation and code in Part 2.

Recall 3.1First justify the problem. Attention computes softmax(QKᵀ)·V. Why does this see "the cat sat" and "sat the cat" identically if we do nothing about position? Point at the exact mathematical property responsible.

Reveal unlocks after a genuine attempt (50+ characters).

Answer

Every query–key score qi·kj depends only on the two token vectors, never on i or j. Permute the tokens and the score matrix permutes with them — attention is permutation-equivariant. A set, not a sequence. Position must be injected somewhere, and where you inject it matters.

The old answer: add a position vector to each embedding. RoPE's answer: rotate each query and key by an angle proportional to its position. Pair up the dimensions of q and k — (q₀,q₁), (q₂,q₃), … — treat each pair as a point in a 2-D plane, and rotate pair i of the token at position m by angle m·θᵢ.

Why rotation specifically? Play with this. Two vectors q (green) and k (gray) start identical; the sliders set their positions m and n, each rotated by position × 45°. Watch the dot product.

Experiment before answering: try (m=2, n=0), then (5, 3), then (8, 6). Then try changing the gap.

Compute 3.2q = k = [1, 0] before RoPE, with θ = 45° per position. q sits at position 7, k at position 5. After both are rotated, q·k = ? (Verify with the sliders — then make sure you can get it from a formula. What rule are you discovering?)

The dot product of two unit vectors is the cosine of the angle between them. q was rotated by 7·45°, k by 5·45°. What's the angle between them now?
Answer

cos((7−5)·45°) = cos 90° = 0. The discovery: R(mθ)q · R(nθ)k = q·k rotated by (m−n)θ — the score depends only on the relative offset m−n, never on absolute position. That is RoPE's entire point: you inject position multiplicatively into Q and K, and attention scores automatically become relative-position-aware. A pair of tokens 2 apart looks the same at the start of the document and at the end.

Each dimension-pair i gets its own θᵢ = base−2i/d (base = 10000): pair 0 spins fast (resolves adjacent tokens), the last pairs spin glacially (resolve document-scale distances). Like the hands of a clock — second, minute, hour — together they encode position at every scale.

Check 3.3RoPE rotates Q and K but not V. Why is V left alone?

Correct

Q·K decides the routing; V is the payload. Rotating V would mean the same word contributes different content depending on its absolute position — exactly the absolute-position dependence RoPE was designed to remove. Clean separation: position lives in the scores, content lives in the values.

Code 3.4Two functions. rope_freqs(head_dim, T): precompute cos and sin tables of shape (T, head_dim/2), using θᵢ = 10000−2i/head_dim. apply_rope(x, cos, sin): rotate x of shape (B, T, H, head_dim), pairing dimension j with dimension j + head_dim/2 (the "half-split" convention Llama uses). Recall 2-D rotation: (a, b) → (a·cosφ − b·sinφ, a·sinφ + b·cosφ).

Real attempt required (150+ chars). Test idea: apply_rope with position-0 tables (cos=1, sin=0) must return x unchanged.

Reference 
def rope_freqs(head_dim, T, base=10000.0):
    inv_freq = 1.0 / (base ** (jnp.arange(0, head_dim, 2) / head_dim))  # (hd/2,)
    angles = jnp.arange(T)[:, None] * inv_freq[None, :]                 # (T, hd/2)
    return jnp.cos(angles), jnp.sin(angles)

def apply_rope(x, cos, sin):
    # x: (B, T, H, hd) — pair dim j with dim j + hd/2
    x1, x2 = jnp.split(x, 2, axis=-1)
    cos, sin = cos[None, :, None, :], sin[None, :, None, :]   # (1, T, 1, hd/2)
    return jnp.concatenate([x1 * cos - x2 * sin,
                            x1 * sin + x2 * cos], axis=-1)

Self-grade:

  • Frequencies come from arange(0, head_dim, 2) / head_dim — exponents 0, 2/d, 4/d, … (a classic off-by-factor bug source)
  • Angle = position × inv_freq via an outer product → (T, hd/2)
  • The rotation formula has the minus sign on the first output half
  • cos/sin broadcast over batch and heads (two inserted axes)
  • Same tables applied to Q and K; V untouched

There is also an "interleaved" pairing convention (dims 0&1, 2&3, …) — mathematically equivalent, but checkpoints are not interchangeable between conventions. Pick one, stay consistent.

Part 4

Attention with GQA

🔒 Locked — finish the compute, check, and code in Part 3.

Standard multi-head attention (MHA) gives every one of the 8 query heads its own K and V. Grouped-Query Attention keeps all 8 query heads but shares each K/V pair among a group of them: our config has 2 KV heads, so 4 query heads share each one. (At the extremes: n_kv_heads = n_heads is MHA; n_kv_heads = 1 is MQA, multi-query attention.)

Why would anyone do this? Not for training speed. Reason it out:

Drill 4.1At inference, a model caches K and V for every past token, layer by layer (the "KV cache" — usually the memory bottleneck for long contexts). By what factor does our GQA config shrink the KV cache versus full MHA?

Per token per layer, MHA caches 2 × n_heads × head_dim floats (K and V). GQA caches 2 × n_kv_heads × head_dim. Take the ratio.
Answer

n_heads / n_kv_heads = 8 / 2 = 4× smaller. That's the entire motivation: 4× longer context in the same memory, 4× less cache bandwidth per decoded token — at a quality cost close to zero (queries stay diverse; it turns out keys/values tolerate sharing well).

Check 4.2Scores are q·k / √head_dim. Why divide by √dk? What goes wrong without it?

Correct

A sum of dk independent products has standard deviation ~√dk. With dk=64 that's scores spread ±8 instead of ±1: softmax saturates, the attention pattern becomes a frozen argmax, and gradients through it die. Dividing by √dk restores unit variance regardless of head size.

Check 4.3Causal masking — token t must not see tokens after t. We set masked scores to −∞ before softmax. Why not the simpler-sounding option: zero out the masked attention weights after softmax?

Correct

Softmax normalizes over everything it sees. Mask before, and the visible tokens renormalize among themselves to sum to 1; mask after, and a token attending 90% to the future ends up with weights summing to 0.1 — its output silently shrinks. In code: jnp.where(mask, scores, -jnp.inf) with mask = jnp.tril(jnp.ones((T, T), bool)). (Row 0 always has its own diagonal entry visible, so no row is ever fully −∞.)

Compute 4.4One query, by hand. After scaling and masking, a query sees two keys with scores [0, ln 3]. Their (1-D) values are v₁ = 2, v₂ = 6. What is the attention output?

e⁰ = 1 and eln 3 = 3, so the softmax weights are [1/4, 3/4]. Now take the weighted sum of values.
Answer

weights = [0.25, 0.75]; output = 0.25·2 + 0.75·6 = 5. Attention output is always a convex combination of value vectors — it can interpolate between what tokens say, never extrapolate beyond it.

Code 4.5The centerpiece. Write gqa_attention(params, x, cos, sin, n_heads, n_kv_heads) for x: (B, T, d_model). Params: wq (d, n_heads·hd), wk, wv (d, n_kv_heads·hd), wo (d, d). Steps you must get in the right order: project → reshape into heads → RoPE on q and k → expand KV heads to match query heads → scores with scaling → causal mask → softmax → weighted values → merge heads → output projection. Write it before peeking. Seriously.

def gqa_attention(params, x, cos, sin, n_heads, n_kv_heads):
    B, T, d = x.shape
    hd = d // n_heads

    q = (x @ params['wq']).reshape(B, T, n_heads,    hd)
    k = (x @ params['wk']).reshape(B, T, n_kv_heads, hd)
    v = (x @ params['wv']).reshape(B, T, n_kv_heads, hd)

    q = apply_rope(q, cos, sin)          # rotate q and k — never v
    k = apply_rope(k, cos, sin)

    rep = n_heads // n_kv_heads          # 4 query heads share each kv head
    k = jnp.repeat(k, rep, axis=2)       # (B, T, n_heads, hd)
    v = jnp.repeat(v, rep, axis=2)

    q, k, v = (t.transpose(0, 2, 1, 3) for t in (q, k, v))   # (B, H, T, hd)

    scores = q @ k.transpose(0, 1, 3, 2) / jnp.sqrt(hd)      # (B, H, T, T)
    mask = jnp.tril(jnp.ones((T, T), dtype=bool))
    scores = jnp.where(mask, scores, -jnp.inf)
    att = jax.nn.softmax(scores, axis=-1)

    out = (att @ v).transpose(0, 2, 1, 3).reshape(B, T, d)
    return out @ params['wo']

Self-grade:

  • K/V reshaped with n_kv_heads, Q with n_heads — the whole point of GQA
  • RoPE applied after the head reshape (per-head rotation), to q and k only
  • KV expanded with jnp.repeat on the head axis, by n_heads // n_kv_heads
  • Scale by √head_dim (not √d_model — another classic bug)
  • -jnp.inf masking before softmax; tril keeps the diagonal (a token sees itself)
  • Final transpose-reshape merges heads back to (B, T, d) before wo

Production note: explicitly materializing the repeated K/V wastes memory; real kernels (and jax.nn.dot_product_attention) handle grouping internally. For learning, repeat makes the semantics impossible to get wrong.

Part 5

The FFN: SwiGLU dense, then Mixture-of-Experts

🔒 Locked — finish all four exercises in Part 4.

Attention moves information between positions; the FFN transforms each position independently — same function applied to every token vector. Modern models use SwiGLU: two parallel up-projections, one passed through SiLU and used to gate the other, then a down-projection:

FFN(x) = ( SiLU(x·Wgate) ⊙ x·Wup ) · Wdown

with Wgate, Wup: (512, 1408) and Wdown: (1408, 512), SiLU(z) = z·σ(z). The multiplicative gate lets the network modulate features smoothly — empirically a consistent win over the plain ReLU MLP.

Code 5.1Write swiglu_ffn(params, x). Three matmuls, one activation, one elementwise product. (jax.nn.silu exists.)

def swiglu_ffn(params, x):

Check: SiLU on the gate branch only; the product happens in d_ff space (1408) before projecting back down.

Mixture of Experts

Recall 5.2MoE replaces one FFN with E = 8 parallel FFNs ("experts") plus a tiny router, and each token is processed by only the top_k = 2 experts the router picks for it. Before reading on: what is the economic argument? What does MoE decouple that a dense network ties together? And predict one failure mode of letting a learned router choose freely.

Reveal unlocks after a genuine attempt (80+ characters).

Answer

The decoupling: parameter count scales with E, but FLOPs per token scale with top_k. Our MoE layer holds 8 experts' worth of knowledge but each token pays for 2. Dense networks force capacity and compute to grow in lockstep; MoE breaks the link — that's how trillion-parameter models run at billions-scale cost.

The failure mode: rich-get-richer collapse. Early in training one expert is randomly slightly better → router sends it more tokens → it trains more, improves more → router sends it everything. You paid for 8 experts and trained 1, with 7 dead. Every practical MoE needs explicit pressure toward balanced routing — coming below.

Compute 5.3The router is a single matrix (d_model, E): logits per expert, softmaxed. A token gets router logits [1.0, −1.0] over two experts. What probability goes to expert 1? (2 dp; e ≈ 2.718, e⁻¹ ≈ 0.368)

p₁ = e¹ / (e¹ + e⁻¹) = 2.718 / 3.086.
Answer

≈ 0.88. These probabilities do double duty: they pick the top_k experts and weight the chosen experts' outputs when combining — which is what lets gradients flow back into the router.

Check 5.4The standard fix for routing collapse is an auxiliary load-balancing loss, added to the main loss: Laux = E · Σe fe · pe, where fe = fraction of tokens routed to expert e and pe = mean router probability for e. Why does minimizing this push toward uniform routing?

Correct

If routing concentrates, some expert has both high f and high p, and f·p blows up; spreading mass minimizes the sum (for f ≈ p, Σf·p ≈ Σp² is minimized by uniform). The gradient flows through the differentiable pe, steering the router away from favorites. The E· prefactor normalizes so perfect balance gives Laux = 1 regardless of expert count. Weighted small (~0.01) — enough to keep experts alive, not enough to override learned specialization.

Code 5.5Write moe_ffn(params, x, top_k=2) returning (output, aux_loss). Params: router (d, E) and stacked expert weights w_gate, w_up (E, d, d_ff), w_down (E, d_ff, d). Strategy for the learning version (and it's a JAX lesson in itself): run every expert on every token with jax.vmap over the expert axis, then combine with per-token weights that are zero outside the top-k. Pieces you'll want: jax.lax.top_k, jax.nn.one_hot, an einsum. Renormalize the top-k weights to sum to 1. Compute the aux loss from Check 5.4.

300+ characters of genuine attempt. Sanity test: with top_k = E and a uniform router, output should ≈ the average of all experts.

Reference 
def moe_ffn(params, x, top_k=2):
    B, T, d = x.shape
    E = params['router'].shape[-1]

    logits = x @ params['router']                      # (B, T, E)
    probs  = jax.nn.softmax(logits, axis=-1)
    top_p, top_i = jax.lax.top_k(probs, top_k)         # (B, T, k) each
    top_p = top_p / top_p.sum(axis=-1, keepdims=True)  # renormalize over chosen

    # dense combine weights: (B, T, E), zero off the top-k
    combine = (top_p[..., None] * jax.nn.one_hot(top_i, E)).sum(axis=2)

    # run every expert on every token (pedagogical; prod kernels scatter/gather)
    def expert(wg, wu, wd):
        return (jax.nn.silu(x @ wg) * (x @ wu)) @ wd   # (B, T, d)
    all_out = jax.vmap(expert)(params['w_gate'],
                               params['w_up'],
                               params['w_down'])       # (E, B, T, d)
    out = jnp.einsum('ebtd,bte->btd', all_out, combine)

    # load-balancing aux loss
    f = (combine > 0).mean(axis=(0, 1))                # fraction routed to e
    p = probs.mean(axis=(0, 1))                        # mean router prob for e
    aux = E * jnp.sum(f * p)
    return out, aux

Self-grade:

  • Top-k selected from softmax probs; selected weights renormalized to sum to 1
  • Combine weights built so non-selected experts get exactly 0
  • vmap maps over the stacked expert axis — one expert() written, eight run
  • The einsum contracts the expert axis with per-token weights
  • aux uses both f (hard counts) and p (soft probs) — gradient flows via p
  • Returns the aux loss instead of swallowing it (the training loop needs it!)

The compute-all-experts trick costs E/top_k = 4× extra FLOPs here. Real systems gather each expert's tokens into contiguous buffers, with capacity limits and all-to-all communication — same math, brutal engineering. Understand this version first.

N_HEADS, N_KV_HEADS, HEAD_DIM = 8, 2, 64

def forward(params, tokens):
    B, T = tokens.shape
    x = params['embed'][tokens]                        # (B, T, d)
    cos, sin = rope_freqs(HEAD_DIM, T)
    aux_total = 0.0
    for layer in params['layers']:
        h = rms_norm(x, layer['ln1'])
        x = x + gqa_attention(layer['attn'], h, cos, sin, N_HEADS, N_KV_HEADS)
        h = rms_norm(x, layer['ln2'])
        if 'router' in layer['ffn']:                   # MoE layer
            ff, aux = moe_ffn(layer['ffn'], h)
            aux_total = aux_total + aux
        else:                                          # dense layer
            ff = swiglu_ffn(layer['ffn'], h)
        x = x + ff
    x = rms_norm(x, params['ln_f'])
    logits = x @ params['embed'].T                     # weight tying
    return logits, aux_total

def init_params(key, vocab=32000, d=512, n_layers=6, d_ff=1408, E=8):
    def dense(key, shape):
        # scale 1/sqrt(fan_in) keeps output variance ~ input variance
        return jax.random.normal(key, shape) / jnp.sqrt(shape[0])
    keys = iter(jax.random.split(key, 200))
    layers = []
    for i in range(n_layers):
        attn = {'wq': dense(next(keys), (d, N_HEADS * HEAD_DIM)),
                'wk': dense(next(keys), (d, N_KV_HEADS * HEAD_DIM)),
                'wv': dense(next(keys), (d, N_KV_HEADS * HEAD_DIM)),
                'wo': dense(next(keys), (d, d))}
        if i % 2 == 1:                                 # odd layers: MoE
            ffn = {'router': dense(next(keys), (d, E)),
                   'w_gate': dense(next(keys), (E, d, d_ff)),
                   'w_up':   dense(next(keys), (E, d, d_ff)),
                   'w_down': dense(next(keys), (E, d_ff, d))}
        else:                                          # even layers: dense
            ffn = {'w_gate': dense(next(keys), (d, d_ff)),
                   'w_up':   dense(next(keys), (d, d_ff)),
                   'w_down': dense(next(keys), (d_ff, d))}
        layers.append({'ln1': jnp.ones(d), 'ln2': jnp.ones(d),
                       'attn': attn, 'ffn': ffn})
    return {'embed': jax.random.normal(next(keys), (vocab, d)) * 0.02,
            'layers': layers, 'ln_f': jnp.ones(d)}

Self-grade the forward pass: pre-norm (rms_norm inside the residual branch), x + on both sub-blocks, RoPE tables computed once and reused by every layer, aux losses summed across MoE layers and returned, unembedding via params['embed'].T. Note the 3-D vs 2-D expert weights are what distinguish MoE from dense layers in the pytree. (A Python loop over layers is fine — jit unrolls it. The fancy alternative, jax.lax.scan over stacked layer weights, compiles faster for deep models.)

The loss

A language model is trained to predict token t+1 from tokens ≤ t — every position is a training example simultaneously, thanks to the causal mask.

Drill 6.2From the token sequence [5, 9, 2, 7], how many (input position → target) prediction pairs does one forward pass train on?

Answer

3: 5→9, [5,9]→2, [5,9,2]→7. In code: inputs = tokens[:, :-1], targets = tokens[:, 1:] — the famous shift-by-one. (So a batch of length T+1 sequences yields B·T training signals per step.)

Check 6.3The loss is cross-entropy: −log qθ(correct next token), averaged. If you did the KL course: which KL divergence, between which two distributions, is this minimizing — and what personality does that direction impose on the trained model?

Correct

Edata[−log q] = KL(pdata ∥ q) + H(pdata), and the entropy term has no θ in it. Pretraining is forward-KL minimization: zero-avoiding, cover-everything. (And the RLHF stage that often follows penalizes reverse KL to a reference — the two directions you studied, stacked in one pipeline.)

Compute 6.4Vocab of 3. Logits [2, 0, 0], correct token is index 0. Cross-entropy loss in nats? (2 dp; e² ≈ 7.389)

p₀ = e² / (e² + e⁰ + e⁰) = 7.389 / 9.389 ≈ 0.787. Loss = −ln p₀.
Answer

−ln(0.787) ≈ 0.24 nats. Note you never materialize the full softmax in practice — log_softmax then pick out the target's entry (numerically stabler than log(softmax(·))).

Code 6.6Write loss_fn(params, tokens) for tokens: (B, T+1) ints: shift, forward, log_softmax, gather the target log-probs (jnp.take_along_axis), mean negative log-likelihood, plus 0.01 × the MoE aux loss. One scalar out.

def loss_fn(params, tokens):
    inputs, targets = tokens[:, :-1], tokens[:, 1:]
    logits, aux = forward(params, inputs)              # (B, T, V)
    logp = jax.nn.log_softmax(logits, axis=-1)
    nll = -jnp.take_along_axis(logp, targets[..., None], axis=-1).squeeze(-1)
    return nll.mean() + 0.01 * aux

Self-grade: shift by one (inputs lose the last token, targets lose the first); log_softmax not log(softmax); take_along_axis needs the targets expanded to match rank; aux loss added with a small coefficient — forget it and your experts will quietly collapse a few thousand steps in.

import numpy as np
import optax

B, T = 8, 128
opt = optax.adamw(learning_rate=3e-4, b1=0.9, b2=0.95, weight_decay=0.1)

params = init_params(jax.random.PRNGKey(0))
opt_state = opt.init(params)

@jax.jit
def train_step(params, opt_state, batch):
    loss, grads = jax.value_and_grad(loss_fn)(params, batch)
    updates, opt_state = opt.update(grads, opt_state, params)
    params = optax.apply_updates(params, updates)
    return params, opt_state, loss          # new state OUT — never mutated

data = np.array(token_ids, dtype=np.int32)  # one long tokenized corpus

for step in range(5000):
    ix = np.random.randint(0, len(data) - T - 1, size=B)
    batch = jnp.stack([data[i : i + T + 1] for i in ix])   # (B, T+1)
    params, opt_state, loss = train_step(params, opt_state, batch)
    if step % 100 == 0:
        print(step, float(loss))            # step 0 should print ≈ 10.37

Self-grade:

  • value_and_grad, not separate loss_fn + grad calls (one forward pass, not two)
  • Everything that changes — params, opt_state — flows in as arguments and out as returns; nothing global, nothing mutated (Part 1's lesson, now load-bearing)
  • jit wraps the whole step: forward, backward, and update fuse into one compiled call
  • Batch shapes constant across steps — change a shape and jit silently recompiles (the classic "why is every step slow" bug)
  • float(loss) only at print time: it forces a device→host sync, so doing it every step would serialize the pipeline

That's a complete, runnable GPT. Feed it any tokenized text (even character-level Shakespeare with vocab ≈ 65 — then your 6.5 ritual predicts ln 65 ≈ 4.17) and watch the loss fall. Model summary — grade yourself

Flow with shapes. tokens (8, 129) → shift to inputs (8, 128) / targets (8, 128) → embed lookup (8, 128, 512). Per layer: RMSNorm → GQA attention: Q (8, 128, 8, 64), K/V (8, 128, 2, 64), RoPE rotates Q and K (never V), repeat KV ×4 to 8 heads, scores (8, 8, 128, 128) scaled by √64, tril mask with −∞ before softmax, weighted V → merge → (8, 128, 512), add to residual. Add to residual. Final RMSNorm → logits via tied embedᵀ (8, 128, 32000).

Loss. log_softmax, gather target log-probs, mean NLL + 0.01·aux. It's forward KL(p_data ∥ q): mass-covering. First-step loss ≈ ln 32000 ≈ 10.37 — always check.

Why each design choice. Pre-norm residuals: stable gradient highway. RMSNorm: LayerNorm minus the parts that don't matter. RoPE: rotations make q·k depend only on relative offset m−n; multi-frequency pairs encode all scales. GQA: share K/V across query-head groups → 4× smaller KV cache at inference, near-zero quality cost. MoE: params scale with E, FLOPs with top_k; the aux loss prevents rich-get-richer expert collapse via the differentiable p in f·p.

JAX disciplines. Pure functions — params in as pytree args, new params out, never mutated (jit freezes anything else as constants). One jitted train_step with value_and_grad, constant shapes to avoid recompiles. Randomness only through split PRNG keys.
