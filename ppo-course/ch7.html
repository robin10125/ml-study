Chapter 7 · Building PPO from Scratch

PPO's core is twenty lines, but the published results depend on a constellation of implementation details that papers mention in passing or not at all. This chapter gives you the full algorithm, the details that decide success, a staged build ladder with a verification step at every rung, and the reference code — machine-checked on this machine, expected output included.

7.1 The complete algorithm

PPO (actor-critic, fixed-window rollouts)
hyperparams: N envs, T steps, K epochs, M minibatches, ε, γ, λ, c1, c2, lr

initialize policy/value net θ; θ_old ← θ
loop until budget exhausted:
  # ---- Phase 1: collect (Ch 1-3) ----
  run π_θold in N parallel envs for T steps each, storing
      (s_t, a_t, log π_θold(a_t|s_t), r_t, done_t, V_θold(s_t))      # NT transitions
  bootstrap value V(s_T) for each env's last state
  compute GAE advantages Â_t (backward recursion, §3.6)
  value targets  R̂_t ← Â_t + V_θold(s_t)

  # ---- Phase 2: optimize (Ch 4-6) ----
  for epoch = 1..K:
      shuffle the NT transitions; split into M minibatches
      for each minibatch:
          r_t(θ)   ← exp(log π_θ(a_t|s_t) − log π_θold(a_t|s_t))
          normalize Â over the minibatch                              # §7.2
          L_clip   ← mean min(r Â, clip(r, 1−ε, 1+ε) Â)
          L_value  ← mean (V_θ(s_t) − R̂_t)²       (optionally clipped, §7.2)
          L        ← −L_clip + c1·L_value − c2·entropy
          Adam step on ∇L; clip grad-norm to 0.5
      (optional) break epoch loop if approx-KL > target              # §6.5
  θ_old ← θ
Everything earlier in the course locates itself here: Ch 2-3 build Phase 1's last three lines, Ch 4-6 build Phase 2's loss.

7.2 The details that decide success

Empirical studies (notably "The 37 Implementation Details of PPO" and Engstrom et al.'s "Implementation Matters") found these contribute as much to reported performance as the clipped objective itself. Learn them as a checklist:

Data & advantages

  • Fixed-window rollouts. Collect exactly \(N \times T\) transitions regardless of episode boundaries; episodes spanning windows are stitched by the bootstrap. Decouples batch size from episode length.
  • Termination vs truncation. A terminated episode ended in the MDP: bootstrap value 0. A truncated one hit a time limit in a still-alive state: bootstrapping 0 there teaches the critic that the state is worthless — a systematic bias. Exact fix: add \(\gamma V(s_{\text{final}})\) to the last reward of truncated episodes (the GAE recursion cuts there anyway, so this is the only entry point). Watch your vector-env autoreset semantics: with gymnasium's NEXT_STEP mode a naive loop silently records one garbage transition per episode (this exact bug cost the reference implementation ~40% of its final score during development — see §7.5).
  • Advantage normalization. Per minibatch: \(\hat A \leftarrow (\hat A - \mathrm{mean})/(\mathrm{std} + 10^{-8})\). The mean-shift is "free" by the baseline argument (§3.1); the std division stabilizes the effective step size across the run. Normalize after GAE, never the returns used as value targets.

Loss & optimizer

  • Value clipping. \(L^V = \max\big((V_\theta - \hat R)^2, (\mathrm{clip}(V_\theta - V_\text{old}, -\epsilon, \epsilon) + V_\text{old} - \hat R)^2\big)\): the critic, too, is held near its data-collection self. Adopted by most implementations for parity with the originals, though ablations find it neutral-to-slightly-harmful — know it, doubt it.
  • Gradient-norm clipping at 0.5; Adam with \(\varepsilon = 10^{-5}\) (not the default \(10^{-8}\)); learning-rate annealing linearly to zero — a slowly tightening trust region by other means.
  • Orthogonal initialization; policy head scaled tiny (std 0.01) so the initial policy is near-uniform and \(\log\pi\) gradients are well-behaved; value head std 1.0.

Diagnostics (what to log)

  • Episodic return — the only number that is the actual objective (§2.6's warning: never the loss).
  • Approximate KL: \(\hat k_3 = \mathbb{E}[(r - 1) - \log r]\) — a low-variance, always-nonnegative estimator of \(D_{\mathrm{KL}}(\pi_\text{old}\|\pi_\theta)\) (better than the naive \(\mathbb{E}[-\log r]\), which can go negative on samples). Healthy: \(10^{-3}\)–\(10^{-2}\); used for early stopping.
  • Clip fraction — share of samples with \(|r - 1| \gt \epsilon\). Healthy: roughly 0.05–0.3 late in training; ~0 means timid updates (or tiny lr), >0.5 means the policy is tearing away from the data.
  • Explained variance of the critic: \(1 - \mathrm{Var}(\hat R - V)/\mathrm{Var}(\hat R)\). Near 1: critic informative; ≤ 0: critic worse than predicting the mean (it will be noisy early — and, late in training on a solved env with near-constant returns, the denominator collapses and the metric becomes erratic; read it with the return curve, see §7.4).
  • Entropy — should decay smoothly; a cliff-dive to zero is premature collapse (raise \(c_2\), check advantage scaling).

7.3 The build ladder — write it yourself

Build in five rungs, verifying each before the next. The reference code/ppo.py (~230 lines) is your answer key, not your starting point. Environment: CartPole-v1; architecture: separate 64-tanh-64 actor and critic heads (§7.2 init).

  1. Rollout collector. N=4 envs × T=128 steps; store the six per-transition fields (§7.1). Verify: shapes \((T, N, \cdot)\); with a random policy, episodic returns ≈ 20-30; stored log-probs match recomputing them from the stored states and actions.
  2. GAE. The §3.6 loop, vectorized over envs, with the truncation bootstrap. Verify: port test_ppo_core.py's brute-force comparison to your function (or run the file against it) — all three GAE checks must pass to 1e-10.
  3. Loss. Ratio from stored vs new log-probs; clipped policy loss; value loss; entropy; combined with §6.7's signs. Verify: on the very first minibatch of fresh data (before any optimizer step), ratios are exactly 1.0, the policy loss equals \(-\mathrm{mean}(\hat A_{\text{norm}})\approx 0\), and approx-KL is 0. PASS 4-5 of the test file checks your clip behavior.
  4. Update loop. K=4 epochs, M=4 minibatches, Adam(2.5e-4, eps=1e-5), grad clip 0.5, lr anneal. Verify: after one update, approx-KL ∈ \([10^{-4}, 10^{-1}]\) — outside that, hunt before training.
  5. Train. 400k steps, seed 1. Verify: the §7.4 expected output — returns through ~150 by 15k steps, ~480+ by 350k, final PASS.

7.6 Where to go next

  • Continuous control: swap the categorical head for the §1.2 diagonal Gaussian (learned state-independent log-std, actions squashed or clipped to bounds) and run MuJoCo/Box2D — the rest of the file is unchanged. That generality is much of why PPO became the default.
  • Scale: more envs (vectorization is the cheap speedup), observation/reward normalization (the remaining "37 details"), recurrent policies for partial observability.
  • RLHF: PPO with a per-token KL penalty against a frozen reference model (§6.6's idea) was the original alignment recipe for LLMs — the ratio, the clip, GAE: everything transfers.
  • Primary sources, now fully readable: Schulman et al. 2015 (TRPO), Schulman et al. 2015b (GAE), Schulman et al. 2017 (PPO); Engstrom et al. 2020 and Huang et al.'s "37 Details" for the empirical fine print.

Write the full two-phase PPO algorithm at the level of §7.1's pseudocode: everything stored per transition during collection, the three lines that close Phase 1, and the exact order of operations inside a minibatch step.

Per transition you must store everything Phase 2 needs that would be wrong to recompute under the new θ. What five things?

Store \((s_t, a_t, \log\pi_{\theta_\text{old}}(a_t|s_t), r_t, \text{done}_t, V_{\theta_\text{old}}(s_t))\) — the old log-prob and old value must be snapshotted at collection. Close Phase 1: bootstrap \(V(s_T)\), GAE backward pass, targets \(\hat R = \hat A + V_\text{old}\). Minibatch step: forward pass for new log-probs/values/entropy → ratio via exp(new−old) → normalize \(\hat A\) → clipped policy loss (min!) → value loss → combined loss with signs \(-,+,-\) → backprop → grad-norm clip → Adam step. Epochs over shuffled minibatches, optional KL early-stop, then refresh θ_old.

Your CartPole agent's value function systematically underestimates good states near the 500-step time limit, capping performance. Explain the termination/truncation distinction, write the exact one-line fix and why it interacts correctly with the GAE recursion, and state what \(V\) is being taught in the buggy version.

At a time limit, is the state worth 0? What does the done-mask do to \(\delta_{T_{ep}}\) there?

Termination = the MDP ended (pole fell): future value genuinely 0. Truncation = external time limit in a live state: the state retains its value, but the done-mask zeroes the bootstrap in \(\delta = r + \gamma V(s')(1-d) - V(s)\), teaching \(V\) that pre-limit states are near-worthless, and the error propagates backward through bootstrapping. Fix: for truncated-not-terminated episodes, \(r_{\text{last}} \mathrel{+}= \gamma V(s_{\text{final}})\). It's exact because the recursion cuts at the boundary regardless — the folded-in value is precisely the bootstrap term the mask removed.

List the five diagnostics every PPO run should log, with the healthy range or shape for each, and write the k3 approximate-KL formula with the reason it beats \(\mathbb{E}[-\log r]\).

k3 uses the ratio and its log together; what property does \((r-1) - \log r\) have for all \(r \gt 0\)?

(1) episodic return — rising, the real objective; (2) approx-KL \(\hat k_3 = \mathbb{E}[(r-1)-\log r]\), ~\(10^{-3}\)–\(10^{-2}\) — pointwise nonnegative (convexity: \(\log r \le r-1\)) and lower-variance than \(\mathbb{E}[-\log r]\), whose samples can be negative; (3) clip fraction ~0.05–0.3 (0 = timid, >0.5 = tearing away); (4) explained variance → 1 as the critic learns (noisy early; unstable when return variance collapses); (5) entropy — smooth decay, no cliff.

Write the complete vectorized GAE function — signature gae(rewards, values, dones, next_value, next_done, gamma, lam) -> advantages, arrays shaped \((T, N)\) — including both boundary rules. Verify before comparing: \(\lambda=0\) must return exactly the TD errors and \(\lambda=1\) (no terminals) exactly discounted-returns-minus-values; pointing test_ppo_core.py's checks at your function must keep PASS 1–3.

One backward loop; at \(t = T-1\) the "next" quantities come from the function arguments; mask both the bootstrap inside δ and the recursion term.
def gae(rewards, values, dones, next_value, next_done, gamma, lam):
    T = rewards.shape[0]
    adv  = np.zeros_like(rewards)
    last = np.zeros_like(next_value)
    for t in reversed(range(T)):
        nonterm = 1.0 - (dones[t+1] if t < T-1 else next_done)
        v_next  = values[t+1] if t < T-1 else next_value
        delta   = rewards[t] + gamma * v_next * nonterm - values[t]
        last    = delta + gamma * lam * nonterm * last
        adv[t]  = last
    return adv

Verify: with λ=0 it returns exactly the TD errors; with λ=1 (no terminals) exactly discounted-returns-minus-values. Both are PASS 2-3 in test_ppo_core.py.

Write the PPO minibatch loss in PyTorch — from new_logp, old_logp, adv, new_v, old_v, returns, entropy to the scalar loss — including ratio, advantage normalization, clipped policy loss, (clipped) value loss, and coefficients. Mark the two places a sign error classically hides. Sanity check to run: on fresh data before any optimizer step, ratios must be exactly 1.0 and approx-KL 0.

Write the policy term as a loss directly: max(-adv*ratio, -adv*clip(ratio)) is equivalent to negating the min — fewer sign hazards.
logratio = new_logp - old_logp
ratio    = logratio.exp()
adv      = (adv - adv.mean()) / (adv.std() + 1e-8)
pg_loss  = torch.max(-adv * ratio,
                     -adv * ratio.clamp(1-eps, 1+eps)).mean()
v_clip   = old_v + (new_v - old_v).clamp(-eps, eps)
v_loss   = 0.5 * torch.max((new_v - returns)**2,
                           (v_clip  - returns)**2).mean()
loss     = pg_loss + 0.5 * v_loss - 0.01 * entropy.mean()

Sign traps: (1) the policy term — maximizing min(·) = minimizing max(−·); negate inside the max, both branches; (2) entropy enters the loss with a minus (we maximize it). Also: old_logp, adv, returns, old_v must all be detached/stored — only new_* and entropy carry gradients.
